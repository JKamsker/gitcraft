## Safety and operating limits

The SVG correction deliberately refuses markers, including otherwise benign arrowheads, and preserves the existing source-view fallback. No marker input above depth 8, OOM/stress fixture or large expansion was generated/run. The check occurs before usvg expansion; it does not rely on post-parse tree counts or reducing final output pixels. Cancellation may suppress queued work or discard abandoned results; an already-running parser/rasterizer is not preemptible, and no hard wall-clock guarantee is claimed. Existing conservative source/node/depth/geometry/raster/output budgets remain the accepted-work contract.

Standalone release does not claim an atomic identity-conditioned rename. It captures what actually moved, inspects ownership afterward and restores only into absence. Foreign entries and uncertain state remain in a named private recovery directory, identified in the returned error. The caller gets an error even if output installation succeeded but lock release is uncertain; the message says the result may have been installed. An existing save error is retained alongside release uncertainty. An unwind has no ordinary return to augment; Drop performs the same preservation-first fallback. Clean owned release removes its private artifacts and returns success. Unsupported hard-link support refuses reservation before touching the output; no overwrite/copy fallback was introduced. Unsuccessful reservation creation can retain its private evidence, named in the error. Windows foreign links which cannot be safely restored are retained in recovery.

The remote metadata reader remains fail-closed when native APIs, complete metadata or a stable bounded snapshot cannot be established. Listing/name bytes plus values are capped at 1 MiB / 1,024 names. Size and name drift is refused before publication; unchanged-size concurrent content drift is additionally checked by existing snapshot before/after access comparison. No atomic metadata exclusion against arbitrary external writers is claimed. Native Linux/WSL runtime has not been exercised here; recording validates allocation ordering and the platform-call contract only. The helper's existing Python 3 requirement and Perl/Fcntl fingerprint requirement are unchanged. No dependency or shared-process changes were added by these three units.
