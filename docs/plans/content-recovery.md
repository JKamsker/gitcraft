# Lost and found by content (#32): implementation contract

Base: accepted integration `ff901aad4346ee409509b60f9c6e7b12689fde44`.
Branch: `codex/content-recovery`; independent of unreviewed working drafts.
Status: read-only search, guarded previews and create-only recovery actions with source-level regressions implemented, unvalidated. No Cargo/runtime test has run; the query/timeline/provenance/preview UI and latest-only background dispatcher are now implemented as source.

The eligible named idea searches remembered text through reflog-reachable commits, dropped stashes, unreachable commits and dangling blobs, then shows content hits with timeline/provenance and guarded recovery. The audit explicitly requires bounded background `fsck --unreachable --no-reflogs`, `cat-file` batching, cancellation, binary/large-object limits and non-destructive recovery previews.

Open PR [#54](https://github.com/JKamsker/gitcraft/pull/54) owns the reflog browser, standalone lost-commit/dropped-stash listing, graph/commit selection and its commit-recovery UI. This branch adds a text-query content-search entry point and matching-blob previews, rather than duplicating those lists. Branch actions reuse the existing generic branch flow; stash recovery is offered only for a validated stash provenance attached to a content hit. No reset, detached checkout or cherry-pick UI is added.

## Read-only discovery and content search

- A user submits a nonempty bounded literal text query. State records request generation and repository lifetime; search and preview work run on background workers. Cancel/closing/replacing a request invalidates the generation; stale results cannot populate a new view or enable recovery.
- Discover reflog commits and unreachable objects using bounded native Git output. Walk reflog-reachable history within an explicit commit budget, and use `fsck --unreachable --no-reflogs --no-progress` for unreachable commit/tree/blob candidates. Do not create refs, index entries, worktree files, reflogs or fetched objects during search. Report shallow/missing/pruned objects and truncation explicitly.
- Reuse the shared Git command context: fallible active-profile routing for ordinary repositories and Practice isolation for marked repositories. Keep binary input/output in the shared bounded process infrastructure; do not introduce a new process runner, host PID scanning, global environment mutation or shell interpolation of queries/content/paths.
- Read-only commands disable replacement objects, lazy fetching, hooks, fsmonitor, external diff/textconv, signatures, maintenance and optional writes as applicable. Fail closed when the installed Git cannot prevent implicit fetching. Source configuration may influence routing, but never execute filters or helpers for scanning blobs.
- Use object IDs as batch input, never untrusted object expressions or filenames. Batch-check types/sizes before content reads; parse exact `cat-file --batch` byte lengths and separators. Reject malformed/truncated frames. Refuse binary/non-UTF-8 content and oversized blobs; bound scanned bytes, object count, tree entries, hits, snippets, stdout/stderr and total elapsed time. Show skipped/limited counts rather than silently claiming a complete search.
- Deduplicate blob content reads while retaining distinct commit/path/stash provenance. Resolve file paths through bounded literal tree listings, not shell commands. Timeline dates come from actual commit metadata; a dangling staged blob has unknown original path/time, which the UI must state.

## Preview and recovery

- Search hits own immutable object IDs plus provenance. Preview rereads and verifies object type, size, raw content and provenance; it shows the exact bytes to recover (bounded text rendering), source commit/path/date when known and the resulting operation. Query text never becomes a regex, revision or shell fragment.
- A commit-associated hit can create a new branch at the pinned commit using existing branch naming/validation and create-only ref semantics. Recheck repository identity/source object and destination absence at execution. Do not move HEAD, existing branches or working files.
- Every content hit can recover its blob to a newly named regular file in the selected repository. Preview names the destination and states that existing files are refused. Use exclusive, non-following creation through verified parent directory handles (or equivalent guarded remote request); never overwrite existing/ignored files, follow symlink/reparse parents, run filters or change the index. Guard stale requests and destination races. A partially failed new-file write must be diagnosed precisely; never delete an unrelated replacement path during cleanup.
- A content hit from a validated dropped stash can restore that commit to the stash list without applying it. Validate the stash commit's parent/tree shape, pin the expected old stash ref, and use compare-and-swap ref update with a reflog entry. Preserve the previous stash and all index/worktree bytes. Ref movement, source pruning, malformed stash shape or cancellation refuses recovery. Raw blobs have file recovery only; ordinary commit hits offer branch/file actions, not a fabricated stash.
- Deliberate recovery is a separate confirmed worker operation and revalidates the preview's guard. Search never mutates a repository to make an object easier to inspect. No dependency on Drafts is introduced.

## Planned evidence

Real repositories: content lost by amend/reset/rebase and reflog expiry; dropped stashes including their index/untracked parents; staged-only dangling blobs; reachable/reflog/unreachable provenance deduplication; Unicode/multiline/no-newline snippets; malformed/oversized/binary blobs and bounded/truncated batch framing; missing promisor objects with a network-helper negative/positive control; cancellation and stale generation/ref/source/destination guards; local/typed-remote quoting; symlink and directory races; create-only branch/file/stash recovery preserving existing refs, real index and working files. Read-only scans must compare refs/reflogs/index/worktree/object packs before and after.

Preserve each implementation unit by commit, push, correct-author verification and exact remote SHA before the next unit or risky test. No Cargo run is authorized until the parent hands over a slot. Final private fmt, strict all-target Clippy, full tests and independent adversarial review are required before the root-owned combined PR.

Implementation detail: recovery-only raw remote calls remain owned by their background caller until `remote::exec` actually returns, including pool/connect waits. Cancellation invalidates the request and stops subsequent queries; the latest queued request cannot launch while that owner remains. No timeout constant is treated as proof of actual completion. Remote new-file publication uses a private Git-metadata scratch file and GNU `ln -T`; cross-filesystem publication refuses rather than replacing data. Local exclusive creation can leave an explicitly diagnosed incomplete new file on disk-write failure, while preserving all preexisting files.

Filesystem root correction: file recovery captures a physical working-root identity and compares it again at the actual create operation. Local snapshots retain an open directory handle: Unix device/inode, Windows volume serial/file index with no delete sharing. Remote publication checks captured `pwd -P` and GNU stat device/inode/ctime with nanoseconds, so root or ancestor substitution fails closed before scratch/publication. If a machine cannot capture a safe identity, search and branch/stash recovery remain available while file recovery is unavailable. Raw object identity checks alone cannot authorize filesystem writes.
