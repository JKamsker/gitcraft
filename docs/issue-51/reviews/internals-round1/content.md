## P2-1: The graft cycle guard inspects inherited GIT_DIR, while the graft writes the selected repository

Locations: `src/git/repository_tools/replacements.rs:122–132`, with isolation contract at `src/git/repository_tools/mod.rs:23–34` and `src/git/repository_tools/guard.rs:78–90`. The ancestry query uses ordinary `git::run_captured`. That transport inherits repository-redirection variables (`src/git/command.rs:194–207`, defaults at86). Snapshot capture and immutable ID resolution use `guard::text`/`read`, which remove GIT_DIR and other redirects. Runner explicitly unsets those redirects in its inner write. Consequently the purported cycle proof and mutation can address different repositories.

**Executed exact-source reproduction:** fixture has selected target commits A→B (B's parent A), and a decoy clone containing the same objects but a replace ref that makes B a root. With no inherited redirect, `git -C target merge-base --is-ancestor A B` returns0, and grafting A's parent to B must be refused. Set GIT_DIR to decoy/.git: the same ancestry command returns1. Exact candidate `replacements::read(target)` correctly captures target/.git; exact `replacements::graft(target, A, B)` then returns Ok and writes a new target replacement. After removing the inherited environment, target `rev-list --parents --all` contains both `B A` and `A B`: an effective ancestry cycle. Git replace itself permits this, so its success does not repair the missing guard. This contradicts the UI's “Cyclic joins ... are refused” and the handoff's effective-graph cycle guarantee.

Actual IDs: A=`dad0cbb51663630b1a9d1bda74168db104ec1c35`; B=`cb773883361166ef85588a27f41057e7e9517ef9`. Decoy replaces B by `6f56e572d102137d6f630dfb81b14b96430f0c9a` with no parents; target cycle replacement is `d13b4b7c6d8a7762e251c2847a0d8d5fca1b089f`.

Correction: execute the code-returning ancestry probe through the same selected-repository, profile-preserving, redirection-clearing bounded transport as capture/resolve/write. Preserve0/1 distinctly and reject all other statuses. Add a regression with inherited GIT_DIR and a decoy effective graph; cover other cleared repository redirections as appropriate. Do not simply clear process-global environment.

## P2-2: All refs browses the inherited repository, then routes object inspection into the selected repository

Locations: `src/git/repository_tools/all_refs.rs:34–41,60–64,83–99,122–149`; UI at `src/repo/repository_tools/mod.rs:415–425`. Every all-refs plumbing command uses ordinary git::run/run_code/run_input, bypassing the isolation helper added for these tools. The request callback only verifies the selected tab path/profile, so it accepts a result produced from the other Git directory. Inspect object then creates an object query on the selected tab path, where the object inspector correctly clears redirects.

**Executed exact-source reproduction:** in the same two-repository fixture, call all_refs::read(target, "") with GIT_DIR=decoy/.git. The returned list contains decoy-only refs/remotes/origin/* and `refs/replace/B`, absent from target. The first invocation without GIT_DIR returns only target HEAD/main. Its history also follows the decoy replacement graph. The tool therefore presents a convincing but wrong repository snapshot, and Follow/Inspect can lead to inconsistent or missing objects. This is not only an older-Git root-enumeration limitation; the reproduction uses Git2.56.0.

Correction: use the same isolation helper for enumeration, immediate-symbolic lookup, pseudoref fallback, tag peeling and stdin history. Retain accepted-code handling for old Git. Add regression coverage that all displayed refs/history and subsequent inspect target the selected repository despite inherited redirects.

## P2-3: Legacy graft metadata bypasses every read/size bound and is passed whole into UI text layout

Locations: `src/git/repository_tools/replacements.rs:56–61`; `src/remote/fs.rs:42–60`; `src/repo/repository_tools/mod.rs:578–580`. The view reads info/grafts using remote::read_to_string, which is std::fs::read locally and unrestricted cat remotely. The result has no size limit and is placed directly in Histories.legacy, then ui.monospace on the UI thread. A FIFO/nonregular local path also bypasses the bounded helper's regular-file check and can block a background worker indefinitely. Process cancellation cannot interrupt a blocking std::fs::read.

**Executed size reproduction:** put a valid ignored comment line of8MiB in disposable target/.git/info/grafts and call exact replacements::read. It succeeds and retains **8,388,610 bytes** for the dialog. Source establishes the absence of an upper bound; I did not attempt a memory-exhaustion fixture, FIFO read, or execute full egui layout. Existing normal Git subprocess caps do not cover this direct file read. The already-added object::files::read provides a bounded, regular-file-checked path on both repository machines and is not used here.

Correction: read legacy graft metadata through a small explicit bounded reader with regular-file checks and cancellation handling; refuse oversized metadata with an actionable message rather than retaining/layouting it. Also include the graft-file witness in relevant freshness guards if its preview is required to remain authoritative. Add oversized/nonregular-path regression checks that do not themselves block.
