## Remaining blocker: FV-R3-1, P1 — compact clip-path DAG bypasses SVG work limits

**Source-confirmed adjacent preexisting path; not introduced by marker rejection.** `src/svg.rs:167–190` counts XML elements/ancestors and rejects use/marker/filter/mask/pattern/foreignObject definitions, but accepts `clipPath`. Definitions can contain two rectangles which both reference the next definition. The definitions are siblings, so increasing reference-chain depth does not increase XML ancestor depth. Source size and element counts grow linearly.

The pinned `usvg 0.45.1` parser caches default user-space clip paths (`src/parser/clippath.rs:29–38,79–86`) into shared structures. The pinned `resvg 0.45.1` renderer does not memoize rendered masks: `src/clip.rs:6–27` allocates a mask pixmap and recursively draws the clip root; `:53–63` routes each clipped child through `clip_group`; `:70–84` recursively applies that child's clip. Two references to the next shared clip are rendered twice. The recurrence for these bounded fixtures is T(d)=1+2T(d-1), hence 2^d−1 mask applications. Reference cycles are not required.

Application `src/svg.rs:247–260` reduces output dimensions from XML complexity but does not bound resolved effect traversal. The fixture is already 8×8, so thumbnail reduction does not prevent amplification. The running parser/rasterizer has no cancellation check (`:82–99,143–264`): abandoning a loader result cannot release a worker while this work runs. An untrusted repository SVG can occupy shared background workers for disproportionate time despite advertised source/node/depth/output limits. No observed UI freeze or native platform runtime beyond the bounded headless calls is claimed.
