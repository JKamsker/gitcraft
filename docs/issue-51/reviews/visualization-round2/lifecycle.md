## Confirmed blocker

### P2: Agent-written search filter does not invalidate the minimap's captured search set

Evidence: `src/repo/authorship_view.rs:158-190` replaces `self.search.matches` when the agent-written filter is applied/refreshed. `:193-201` clears it when disabled. Neither path marks the minimap dirty or cancels/replaces its Reader. By contrast ordinary search completion/clearing in `src/repo/navigate.rs:476-583` explicitly marks the minimap dirty. `src/repo/graph_view/minimap.rs:89-104` captures the search Arc only when `dirty` is true, then retains completed bins. `:73-75` computes each hit marker from that captured set.

Source-derived reproduction (not a newly executed interactive fixture): allow a wide history view's minimap to complete with ordinary/empty search matches; turn on the Agent-written filter without a history reload. Search results and row highlighting change, while minimap bins continue to reflect the previous search set. Conversely, prepare a minimap with agent hits then disable the filter; yellow hit markers remain until some unrelated invalidation. A queued old minimap is also free to complete after this change because its generation was not retired. No mutation of the new Arc affects the captured immutable old set.

This is present before this correction series (the old HashSet replacement/clear also omitted dirtying). It is a candidate integration defect, not evidence that Arc sharing itself introduced stale mutation. Fix both the filter refresh and clear paths through the same minimap invalidation mechanism used for other search transitions. A pure headless regression should first populate a completed/in-flight minimap, toggle the actual agent-filter action, and prove the next accepted model represents the new hit set and does not accept the old result. The parent has acknowledged and is implementing this integration correction; that future commit is not part of this disposition.

## Lifecycle, graph API and bounds checks

- Reader replacement retains one running slot until completion and at most one pending replacement (`history_reader.rs:29-87`). Cancellation increments generation, drops pending captures and cancels the running child token. Late completions fail the generation check. Reader Drop cancels its token. `spawn_or` supplies a private error completion for rejection/panic/cancellation, so Reader does not depend only on the tab result channel. The two independent Reader fixtures cover the owned ambient token, replacement coalescing and stale-result suppression; they do not prove a running OS process is reaped.
- Suspend replaces the tab task lifetime and its public receiver, drops each private Reader/cache and prevents sleeping feature polls. On resume the tab reloads with a new lifetime. The blocked-worker fixture verified stale private results cannot rehydrate sleeping state. Bulk cache destruction can still take time on the UI thread; the docs correctly describe that as follow-up, not an async destruction guarantee.
- Ordinary reload/rebuild replaces the Graph, queues band/topology work and invokes `cancel_minimap` (`load.rs:566-624`). Band layout replacement dirties the minimap before the next prepare (`branch_bands.rs:173-181`). Search completion/clear paths create fresh immutable search snapshots and dirty the map; agent-filter paths are the exception reported above.
- Checked the temporary ghost Graph swap (`graph_view/mod.rs:95-114`, `ghost/mod.rs:153-187`). **Nonfinding:** `graph_view/mod.rs:335-337` calls `history_minimap` only when `!ghost`; `prepare_minimap` is reached only from that production entry point. The ghost snapshot is neither prepared nor drawn as a minimap, and Graph is swapped back before later ordinary frames. A preliminary ghost invalidation concern was withdrawn after tracing this guard.
- Immutable row hash/tag metadata is constructed with each ordinary and banded layout, rather than separately reading a concurrently replaced commit vector. Graph clones share the entire immutable row allocation, including edge arrays. Arc mutation used while constructing layout does not mutate an already published Graph. Existing UI layout/index construction is still proportional to loaded history (`load.rs:607-613`); O1 fixes minimap capture, not every history operation. Existing commit/ref captures, result drops and layout work must not be advertised as constant-time or entirely off-thread.
- Minimap storage is capped at 512 bins and the displayed lane mask at 24 lanes, with explicit coverage text. Build checks cancellation per row and still scans the loaded Graph; it does not scan repository history independently. No bound on total graph edge complexity or RSS beyond the loaded snapshot is inferred from the bin cap.
- Export capture and publication remain local, create-only and directory-pinned. The tested Unix publication uses exclusive/no-follow final creation relative to the retained parent, mode 0600 (`export.rs:44-87`). Cancelling before publication creates no file. Once write/sync starts, cancellation does not preempt the filesystem operation and failure can leave the newly created PNG incomplete; docs acknowledge this. Export bytes have a 64 MiB cap. Per-ancestor opens may block a worker on filesystem latency; this correction avoids blocking the UI but does not add per-open cancellation or an I/O deadline.
- Profile validity compares profile paths, not a monotonic generation. Same-path edits and A→B→A changes can escape invalidation; the documentation explicitly leaves this for parent integration. This review does not certify profile-generation binding. Tab close/replacement still cancels the owned token independently of profile path equality. Parked worktree postcard draft persistence is likewise not claimed.
