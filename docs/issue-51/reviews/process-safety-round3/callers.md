## C-R3-1 — P2: bisect still discards ownership failures before cancellation/result normalization

**Disposition: unresolved caller blocker.** Sources: `src/parallel_bisect/session.rs:180–189,228–239,514–574`, `workspace.rs:49–75,118–134,351–360`, `session.rs:419–420`.

`bisect()` maps **every** `prepared()` error to `Outcome::Cancelled` when the session stop flag is true (`session.rs:185–188`). It does not distinguish a guaranteed non-dispatch/confirmed cancellation from an unknown native/remote finalization, failed recovery, or missing cleaned receipt.

The initialization path makes this observable without even the later generic cleanup warning:

1. `Workspace::open()` has acquired its claim and is waiting for its initial checked CLEAR (or private-directory initialization).
2. The user requests cancellation, setting the session's stop flag. The actual operation returns an ownership error, for example `could not finish owned process: <recorded failure>` or a missing/mismatched cleanup receipt.
3. `Workspace::open()` returns that error. Its partially initialized Workspace has `closed=true`; Drop performs no CLEAR, correctly preserving evidence.
4. `prepared():230` returns via `?` before reaching the close-warning branch at 233–237.
5. `bisect():187` discards the ownership error and the session emits `Done(Cancelled)`. No uncertainty warning or original failure survives this path.

These are static branch inputs and an exact control-flow derivation, not an executed cancellation/helper fixture. The failure contract is already present in `Workspace::execute()` and the actual machine owner; no hypothetical new failure mode is needed.

There is a second branch of this same result-preservation defect. In `Run::round()`, a received worker result is discarded at 541–542 if cancellation is set or an earlier outcome was selected. A failed test stop/recovery is therefore ignored after a first result, and the final stop check at 571–572 also overrides an already collected error. `Slot::test()` invalidates the Workspace on a runner error, so ordinary `prepared()` completion usually emits a generic ownership-uncertain close warning. This is a meaningful safeguard: it prevents claiming that every such case has no warning. It still loses the original owner/cleanup error, and the initialization case above has no such fallback warning.

Finite correction: preserve ownership/execution errors before cancellation normalization, and consume/report late worker ownership errors while joining every slot even after a search outcome or cancellation. A successful search answer may coexist with a concrete cleanup warning; it must not erase that warning's original error. Use an explicit confirmed/no-dispatch cancellation distinction or conservatively preserve errors. Add pure injected-result tests for (a) cancelled + setup ownership error with no Workspace returned, (b) cancelled + worker cleanup failure, (c) selected answer + later worker cleanup failure, and (d) confirmed normal cancellation. No actual Git, shell target, Service, process, native filesystem race, or SSH fixture is required for this correction.

This is the R2 error-before-cancellation invariant and the accepted design's requirement to preserve primary/cleanup failures, applied to the actual bisect caller. It does not reopen the old workspace-claim implementation or introduce a new containment/power-loss requirement.
