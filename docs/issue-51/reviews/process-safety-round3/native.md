## Native integration assessment

**Actual-machine authority and namespace.** `workspace_lock.rs:141–219` retains the directory, primary/fence/generation files and external anchor, and checks current named identities and exact anchor bytes. Initialization uses create-new, private regular single-link files; incomplete/replaced namespaces refuse rather than repair themselves into a second lock namespace. Claim acquisition (`225–277`) takes primary then fence before publishing and synchronizing a random generation; PID, clock and heartbeat are absent from this authority. Fence acquisition (`283–306`) revalidates identities, anchor and generation and refuses if the old primary is no longer locked. Neither claim nor fence Drop dispatches, clears, retires or rewrites generation. Canonical root construction and caller sequencing are T3's scope.

**Record publication and dispatch handoff.** `native_owner.rs:464–490` installs EOF cancellation before waiting for the actual fence. The owner creates a generation/kind/anchor-bound v3 record before target submission (`519–531`; `workspace_authority.rs`). `WorkspaceFence::publish_record:308–320` writes through the held directory with create-new and requires write, file sync and checked close; the injected production publication routine refuses every failure stage. Dispatch releases the fence only after successful Service submission has installed the same sticky cancellation token (`native_owner.rs:600–632`). A cancelled queued request is rejected both by queue maintenance and immediately before spawn (`processes.rs:385–397,622–631`). A cancellation racing a successful spawn still has an actual Service-owned child, and no stopped receipt can precede that ticket's terminal result. A failed submit produces only NotDispatched proof; arbitrary post-submit failure cannot use that branch. This is a static trace plus boundary recordings, not a live scheduling proof.

**Full mutation fence.** Mutation mode retains the actual helper's fence through target stop/reap, successful native ledger finalization and durable terminal receipt (`native_owner.rs:694–712`). Any ordinary Rust error passes through entrypoint shutdown/join before the outer fence is dropped. The fence is held by the machine doing the work, rather than substituted with a client-side lock. Private directory creation is also limited to the expected workspace sibling and mutation authority (`532–568`). These boundaries align with the original finite claim design.

**Exact recovery evidence and partial failure.** `workspace_ledger.rs:93–139,174–280` validates manifests, name/generation/kind/anchor binding, exact record bytes and authenticated receipt bytes before control. It refuses collisions, orphan/changed proofs, unknown formats and foreign endpoint kinds. Actual stop proof is cached with create-new/write/sync/checked close before CLEAR input is prepared. Reads and decoded allocations have explicit individual, 4096-owner, 64MiB inventory and 40MiB manifest limits. `verify:283–299` checks the named ledger identity and exact retained record presence/bytes; external CLEAR proof and final receipt verification belong to the separate caller review.

Only code0 plus complete delivery enters ledger completion (`native_owner.rs:695–707`; `workspace_ledger.rs:390–391`). Production `finish_cleanup:394–405` orders verify→publish complete manifest→retire every endpoint→prune→public cleaned receipt. `complete:321–387` keeps all old records/caches until every retirement succeeds, and leaves the new complete manifest throughout partial pruning. Subsequent recovery can reconstruct exact missing records from it. Independent injected execution stops at each failed stage and never proceeds to later retirement/prune/success. This is process-crash evidence handling under the stated design; directory power-loss durability is explicitly unclaimed.

**Cached-proof retirement boundary specifically checked after the remote review warning.** Native `Endpoint::retire_proven:158–171` authenticates the cache **and then** opens the currently named private endpoint directory and calls `remove_checked("terminal", exact_cached_receipt)`. `private_directory.rs:96–119` reads the current terminal relative to the held directory and requires byte equality before deletion. A replacement private directory with absent terminal deletes nothing; a changed/foreign terminal refuses; no unrelated fixed files or directory pathname are removed. This differs from the reported Python/Perl regression that used cached proof without authenticating the current pinned receipt. Ordinary retirement likewise verifies the opened terminal before removal (`receipt_retirement.rs:11–43`). Windows deletes the actual retained terminal HANDLE; Unix unlinks a single component relative to the retained private directory. It does not claim protection against an arbitrary malicious same-user writer replacing an entry between its exact read and unlink. That stronger threat was not part of this bounded correction.

**Unix identity and Windows resource ownership preserved.** `unix_anchor.rs` and packaged `group_anchor.c` still retain the live direct-child group anchor through final owned-group signaling; observing user status does not reap it. The target closes the private status/control descriptors. No host PID selector supplies signal authority. Windows retains owned process/Job/thread HANDLEs and does not reopen a process by PID. Create/resume failure cleanup remains handle based, and inherited ownership handles are disabled. Unknown proof never authorizes endpoint retirement or workspace removal.
