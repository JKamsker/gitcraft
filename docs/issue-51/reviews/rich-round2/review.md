## Honest limits and retained design

- Semantic Find remains a separate reading layout. It highlights and steps real matches; Copy current reading row is reachable after a hit. Closing restores the ordinary rich view. Source-anchor navigation/selection transfer back to the original rich row is still absent; this was not required to reject the accepted reading-layout design and is not claimed as implemented.
- Construction remains synchronous on the UI thread. A document exceeding32,768 logical rows or20 MiB rendered text explicitly refuses the whole reading, clears retained rows/results and says no partial result count is shown (`rendered.rs:74–85,243–251`). The bounded many-line refusal test passed. These are logical-row/text budgets, not a claim of exact total heap accounting or a native frame-rate guarantee.
- Search scans whole logical rows to preserve regex/word boundaries. One very long row can exceed the nominal scan time slice; the response explicitly discloses this. Initial build/segmentation and rich style construction also are not governed by the scanner's4 ms slice. This source-established limitation remains; no giant/OOM or timing stress fixture was run or inferred.
- Archive/download/expanded/text/count caps remain. Oversized/unsupported licence/changelog content can be unavailable but is now explained. The lookup trusts allowed public registry name/version provenance and archive identity checks; it does not verify archive bytes against lockfile checksum/integrity. Private-source packages are not sent to the public registries. No new source-authority bypass was demonstrated.
- Per-side results are independent even if the earlier side fails. A slow earlier fetch can still delay the later side because fetching remains sequential; finite request bounds exist. This is not a claim of parallel fetching or instant network cancellation.
- Metadata reply ownership still checks captured connection context and drops replaced receivers/task scopes. Completed cache contains public successful metadata; it is not a decrypted/private-plaintext cache. No profile/network timing, real proxy/registry interoperability or cancelled-I/O runtime was tested here.
- Reading parity remains semantic: config previews retain their existing display cap; notebook extraction is bounded and image pixels are not OCR; structural syntax does not imply search of omitted unchanged source; unavailable binary extraction stays unavailable. No hidden raw patch was substituted to manufacture broad coverage. No SOPS/plaintext cache guarantee is inferred for integration with the separate encrypted feature.
- The harness stubs theme/application/task/context plumbing and does not certify full-window keyboard/focus routing, native platforms or asynchronous scheduler behavior. Actual route/generation plumbing was source-reviewed, with the exact writer headless integration logs as additional evidence. No process runtime/cancel/kill test, full suite, CI/PR, external registry/service call, external mutation or subagent was used.
