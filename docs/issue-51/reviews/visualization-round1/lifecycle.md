## Cancellation API/test contract gap (not a demonstrated production child leak)

### C1 — Running analysis does not observe its active callback (P2)

`src/git/activity/process.rs:8,23–45,60` consults `active()` only before invoking Git and after the synchronous wait returns. It supplies no active callback to Service `Options.cancelled`, nor to the remote request's running cancellation. The inherited task Cancellation correctly handles Reader closure/supersession, and production Reader passes the same owned token into active(). Thus ordinary view close/replacement cancels running Service commands despite this callback gap. App::switch_profile also clears old tabs through restore_state, dropping their Scopes/Readers. I did not establish a production descendant leak in those normal routes. A separately changing callback cannot terminate an already running command.

**Deterministic source repro:** the existing ignored `git::activity::tests::cancelling_a_running_analysis_stops_process_descendants` (`tests.rs:312`) sets active to `elapsed < 100 ms`, and runs `sleep 0.5; touch marker`. There is no ambient task token in that direct test. Current code waits until touch has executed, then notices false and returns "Analysis cancelled". The final `!marker.exists()` assertion must fail. No need to execute this process test to establish the code path. Ignoring it for containment leaves this implementation failure pending; fixing shared process ownership alone will not fix it.

**Production distinction:** settings::profiles::apply may change PROFILE_CONFIG Some(path)→None on an edit to the current profile without dropping tabs. Atlas/growth invalidate their profile only when their window is rendered, so a hidden view can have active()==false while its ambient token remains uncancelled; the already-started command continues until completion/deadline, then rejects output. This establishes delayed invalidation, not a demonstrated unbounded child leak or cross-profile publication. Ordinary switching still cancels via tab ownership.

**Correction:** choose and document one contract: observe a clonable cancellation/profile guard during I/O (or poll the borrowed callback while retaining/cancelling an owned ticket), or explicitly make active() a stage/result validity check while cancellation is supplied by the owned task token. The latter requires replacing the misleading imported direct-callback test with a meaningful production Reader/owned-token cancellation test. Apply equivalent lifetime behavior remotely using the parent's safe owner implementation; do not add another raw-PID stop mechanism or one watchdog per analysis. Preserve no-lazy-fetch, output/deadline limits and postflight validity. Add recording state tests before owned-child gate, then execute the owned-token regression only after containment authorization. This contract/test correction is required before claiming the ignored test passed, but is not one of the independent FAIL blockers below.

## Blocking findings

### B2 — Suspension neither retires private readers nor clears new caches (P1)

`src/repo/lifecycle.rs:152–188` cancels the old tab Scope, replaces the main Msg channel, and clears original history/graph/index caches. It does not cancel Reader generations, clear pending requests, or release the newly added band/topology/minimap/activity/atlas/growth state. `src/repo/messages.rs:388–391` polls band/topology/activity readers **before** its sleeping guard. These Readers return through independent channels (`history_reader.rs:48–84`), so replacing `self.rx` does not invalidate their completed answers.

**Deterministic interleaving:** a band job completes and sends Graph on Reader's private channel, but UI has not polled it; tab suspends and clears Graph; next background `poll_as` calls poll_branch_bands; unchanged Reader generation accepts the old graph and writes it back (`branch_bands.rs:161–168`). Topology behaves similarly. A pending Reader not yet dispatched can also be submitted after suspension using the newly created live tx token. Existing generation checks protect replacement via Reader::queue/cancel, but suspend calls neither. Thus old results can repopulate suspended state and expensive cached activity/tree snapshots stay retained for every suspended tab.

**Correction:** add a visualization lifetime reset in suspend: cancel/retire all Reader generations and pending jobs, clear heavy result caches (and narration/animation state that points into them), and ensure sleeping polls cannot dispatch or accept old work. Preserve user preferences separately and rebuild derived data on resume. Release large snapshots away from the UI where necessary, consistent with existing large-history disposal. Add pure deterministic tests for completed-before-suspend, running-during-suspend, pending-before-suspend, then resume; assert no old result, new spawn or retained heavy cache. Cancellation alone is insufficient for an answer already in the private channel.

### B3 — Count limits allow gigabytes of expanded path/author allocation (P1)

`src/git/atlas.rs:101–116` clones full author name/email into every changed file's BTreeMap, then formats another full contributor string into each node. No identity length/expanded memory budget or identity interning exists. `ensure` stores full prefix bytes twice, once in Node.path and again as the paths map key. `src/repo/growth.rs:47–86` similarly materializes every full directory prefix in its BTreeSet; it bounds **entry count**, not allocated path bytes. The 16 MiB command stream and 200,000 entries do not bound these expansions to a reasonable application budget. Both loops can run without active checks for the full expansion.

**Safe arithmetic witnesses executed by reviewer (no production path/OOM fixture):**

* Generate 512 distinct paths, each 123 components of 255 ASCII bytes (unique first component), total path length 31,487. These satisfy depth <=128 and path <=32,768, only 512 files. A tree stream estimate including 120 bytes metadata per file is **16,182,784 bytes**, below 16 MiB. Expanded paths contain **62,976 entries**, below 200,000; their payload sums to **999,492,096 bytes**. Atlas's two stored full-path copies alone need **1,998,984,192 bytes**, before maps/nodes/history/allocator overhead. Growth needs almost a gigabyte just for expanded key payload plus its source clones. These are legal object-tree paths even if a local checkout cannot materialize every such path.
* A single 1 MiB author identity and 10,000 short changed paths fit a 16 MiB raw log record (about 2.55 MiB with generous 150-byte change records). Atlas creates approximately **10,485,760,000 bytes** of author-key payload before the reverse aggregation, and later huge per-node contributor strings. Git metadata is repository content; it has no author-length bound here. An analysis action can exhaust app memory before reaching any advertised count limit.

**Correction:** intern authors once and retain small IDs/Arc references, cap metadata/display text sensibly without silently conflating distinct identities, and impose a cumulative expanded-byte/allocation/work budget before allocation for both Atlas and growth tree rows. Parent-path IDs or component storage avoid repeated full-prefix copies. Check cancellation within file/path expansion and reverse aggregation. Add small synthetic budget tests that refuse early without allocating the extrapolated gigabytes; the witness itself need not be run through production at hostile sizes. Counts/depth limits should remain, but cannot substitute for byte budgets.

## Additional changes needed for the stated performance/UI-thread contract (P2)

### O1 — Minimap's asynchronous build begins with a full deep Graph clone on the UI

`src/repo/graph_view/minimap.rs:86–96` executes `self.graph.clone()` during painting/preparation before queueing the worker. Graph holds a Vec<Row>; each Row has a HashMap plus boxed incoming/outgoing arrays (`src/graph.rs:15–38`). This is an O(loaded rows + edges) deep clone with potentially several allocations per row on the UI. Repeated search invalidations pay this cost even when latest-only Reader will cancel the resulting work. 512 output bins cap paint work but do not cap this front-end scan/copy. Full index/refs snapshots in other queue helpers should likewise be assessed for large histories.

Use an immutable Arc graph/row snapshot, or cache compact immutable minimap input while constructing the graph off-thread. Add a recording/perf-oriented fixture with a large synthetic graph proving the UI capture operation does not deep-copy every row. This is a concrete full UI traversal, though reviewer did not run timing measurements and does not assert a numeric frame-time result.

### O2 — Export parent capture performs filesystem traversal on the UI

`src/repo/postcards/mod.rs` save branch directly calls `export::Destination::capture` after the file dialog, before queueing. Capture opens and checks every ancestor directory (`export.rs:89–142`), including possible mounted/network/FUSE folders selected by the user. A slow open blocks egui. Keep the native chooser behavior, but perform capture plus create-only publication in the existing owned worker. Capturing after queueing remains safe: replacement symlinks/reparse points are rejected; Unix final create remains relative to held parent; Windows held ancestor handles retain delete-sharing restriction. Do not weaken the create-only/no-parent-replacement defenses.

These P2 observations should be resolved to claim that all new reads/export preparation avoid blocking work on the UI. They are separate from UI feature-semantic review.

## Positive findings and practical limits

* Reader retains at most one running and one pending replacement, cancels child tokens, suppresses stale generations, handles disconnected result channels, and routes queue rejection/cancellation/panic through a feature failure sender via spawn_or. Its ordinary same-view replacement mechanism is coherent. The missing case is tab lifetime retirement, not normal replacement.
* Local reads use Service with 120-second deadlines, 16 MiB stdout/64 KiB stderr, background process capacity, ambient tab/Reader cancellation and bounded pipe drains. No new process discovery/signaling controller was added. Remote analysis correctly encodes remote cwd, uses bounded request transport and preserved diagnostics, but inherits the known unsafe shared remote timeout selector; parent's ownership prerequisite must land before full runtime gates. This report does not treat the inherited controller as a newly introduced selector.
* History pins distinct local/remote/tag/HEAD roots and pages with explicit per-page count, 10,000-tip/64 MiB cumulative limits, shallow and partial labels. Calendar/contributor summaries share one immutable snapshot; date changes use cached history. `--skip` restarts traversal for each 250-record page: at the 100,000-commit limit this can revisit roughly 20 million commit positions. This is bounded and off-thread, but deserves a true cursor/stream or measured large-repo cost; do not describe it as one physical Git walk. There is no overall analysis deadline across 400 commands.
* All new readers use --no-lazy-fetch, --no-replace-objects, hooks disabled and signature display disabled. Atlas may need local blobs for ls-tree -l sizes and mailmap may need local blobs; absent promised objects should error, never fetch silently. Existing missing-object tests and diagnostics support this behavior. Per-command bounds can fail before cumulative partial-history coverage is produced; UI should continue reporting that as an error rather than full coverage.
* Mailmap is resolved once after history paging, preserving Git precedence; configured blob resolves to immutable OID and actual blob access detects missing objects; configured file is fingerprinted before/after. Worktree .mailmap is loaded once in Git's check-mailmap call, avoiding split identities across log pages. No app mutation is needed. Large map files/Git parsing itself remain bounded by child timeout/output, not by a native Git memory limit; no stronger sandbox claim is warranted.
* Audio has one lazy worker, two-slot dispatch channel, a sink backlog capped below two queued cues, <=200 ms synthesized cues, and device release after five seconds idle. UI uses try_send rather than device opening. Tests substitute recording dispatch; no device playback was validated. Static sender leaves one sleeping thread for process lifetime; this is a fixed bound, not a per-cue leak. Native Windows/Linux compilation and actual devices remain outside supplied macOS evidence.
* Unix export uses openat from held NOFOLLOW directory handles, CREATE|EXCL|NOFOLLOW, mode0600, preserves existing files and avoids raced-name deletion. Windows holds each ancestor with reparse-point checks and no delete sharing before create_new. Cancellation is checked before file creation, not transactionally during write/sync; disk error may leave this newly created file incomplete and correctly reports that. Do not claim atomic all-or-nothing file publication.
* Postcard disclosure/render snapshots cap range 200 and cleaned title/name/message text; anonymized render input removes original identity/message fields. Profile-path changes and closing remove disclosure data and cancel stale work. Reader queues/render CPU are bounded in ordinary use; PNG encoding itself is not interrupted until it returns. Profile matching uses config path equality, not a profile generation/content fingerprint; same-path edits or rapid A→B→A changes are not distinguished. A generation-bound profile owner would be stronger and should align with parent's profile integration.
