## P1 — nested SVG markers bypass expansion bounds before rasterization

Production source: `src/svg.rs:143–176,224–246`. Dependency source: pinned `usvg0.45.1/src/parser/marker.rs:62–70,166–212`, as selected by the application Cargo.lock.

The preflight rejects `use`, `filter`, `mask`, `pattern` and `foreignObject`, bounds source bytes, XML element count and XML ancestry depth, then passes the document to `usvg::Tree::from_data`. It permits `<marker>` definitions and `marker-mid`/`marker-start`/`marker-end` references. usvg expands marker children anew at every applicable path vertex. Its cycle check only rejects a marker already on that recursive branch; a chain of **distinct** marker IDs is valid and passes it.

A definition containing a four-point path with two interior vertices and `marker-mid` referring to the next definition doubles the expansion at each level. Definitions are siblings under `<defs>`, so XML ancestry depth remains small. The parsed tree expands before the complexity-based thumbnail/output pixel calculation at `svg.rs:233–238`. That complexity counts source elements and path attribute length, not expanded marker instances. Lowering the final image size cannot bound this earlier allocation/work. `render()` has no cancellation callback or token check within parsing, so dropping/forgetting the view cannot interrupt expansion already running in the task worker.
