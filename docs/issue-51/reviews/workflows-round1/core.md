## B2 — P1 ownership defect, plus P2 unvalidated timeout contract: Docker cleanup targets a mutable name

`reproducer.rs:142–148` runs `docker inspect ... NAME`, compares the returned label, then runs `docker rm --force NAME`. The checked owner belongs to the container which occupied NAME at inspect time. It does not bind the later destructive command to that container. If the owned container exits/is removed after inspect and another container takes the name, cleanup removes the replacement. Name prefixes/tokens/labels do not make the final name lookup identity-stable. `OwnedContainer::Drop` repeats this same script.

**Recording-only evidence:** the exact production cleanup format was run against a fake Docker recorder. Its inspect returned the correct owner token, then the recorder modeled replacement before rm. Production script exited0 and issued `rm --force gitcraft-reproducer-recording`, resolving to `foreign-replacement-id`. No Docker runtime, real deletion, process signal or container was used. Artifacts: `recording_cleanup_probe.py`, `cleanup-recording.jsonl`, `cleanup-probe-result.json` under the artifact directory above.

Correction: obtain and retain the immutable container ID for the operation, validate its owner, and address cleanup by that ID; never inspect by one mutable identity and remove by a later mutable lookup. Cover absent/already removed/mismatched owner/replaced name/interrupted creation and cleanup failure using recording cases before real owned fixtures. Preserve cleanup failure evidence rather than only best-effort logging.

Additional **source-level** timeout gap, not a Docker runtime observation: the run vector `reproducer.rs:106–135` does not override the selected image ENTRYPOINT. Docker appends positional `sh -c ...timeout...` to an image's ENTRYPOINT, so an image with an entrypoint that does not forward arguments can bypass the intended internal timeout/test command entirely. The stated 125-second containment fallback in Drop is therefore not established for the accepted image set. [Docker’s primary run documentation](https://docs.docker.com/engine/containers/run/) specifies these entrypoint semantics. Pin an explicit entrypoint/control command, verify required tools, and bound Docker inspect/control/cleanup calls too: image inspection and cleanup currently use `git::run_shell` without a timeout or RunStop binding. The Stop button's RunStop is only connected to `contracts::observe`; it cannot stop a stalled preliminary image inspect. Then run real success/failure/timeout/cancel/crash/cleanup fixtures on a supported Docker host. Docker is absent here, so those gates remain **UNVALIDATED**, independently of the observed ownership design defect.
