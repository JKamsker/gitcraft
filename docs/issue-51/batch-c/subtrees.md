# Subtree lifecycle — implementation WIP

Original source: issue #49, “Subtrees”: register a vendored folder's source repository/branch, pull upstream changes, inspect local edits, split and send them back, explain squashed versus full history. Git's primary [manual](https://github.com/git/git/blob/v2.51.0/contrib/subtree/git-subtree.adoc) and [helper source](https://github.com/git/git/blob/v2.51.0/contrib/subtree/git-subtree.sh) informed the command contracts and explicit association step.

The repository action “Subtrees: register, update, inspect and publish vendored folders” opens `repo/repository_tools/subtrees.rs`. Its backend is `git/repository_tools/subtrees.rs`.

- Registration stores a relative non-overlapping folder, configured source remote, branch and future import mode in a bounded direct application ref. The configured fetch/push addresses may differ. Missing folders can be imported; existing Git-subtree imports can be updated directly.
- For plain vendored folders without import metadata, Fetch then Inspect establishes an explicitly reviewed baseline. Associate creates a candidate with exactly the existing application tree, parents it to the full upstream commit or one condensed upstream-tree commit, and records standard subtree trailers. Its patch is reviewed and accepted before later imports. This does not guess an unknown historical upstream version or overwrite local folder contents.
- Fetch is explicit and writes a unique application ref, without moving the original branch or FETCH_HEAD. Prepare update uses that immutable fetched OID with `subtree add/merge` and actually includes `--squash` only for squashed imports. Full imports retain upstream ancestry. Registration does not convert earlier history.
- Every update/association/split starts in a fresh retained, locked detached worktree. Only acknowledged creations acquire an owned native identity. Candidate commands reuse the existing deferred worktree metadata/link/directory checks, through two narrow Git-internal entry points. Conflict resolutions are staged in the candidate; Continue commits that merge, rather than restarting the helper or discarding resolutions. Interrupted/failed work remains inspectable. Close preserves the directory and objects.
- Accept requires the exact original direct branch/OID and a clean original checkout, including ignored untracked files. It checks the reviewed immutable candidate and delegates to the existing guarded history checkout transaction. Accepting is persisted before dispatch; uncertain outcomes are retained and explicitly reconciled against the original branch/result, without rollback or blind retry. This depends on the parent-owned final shared history integration and its acceptance.
- Local inspection separates committed folder changes, staged changes, unstaged changes and untracked paths. Before the first accepted import, comparison against a fetched source is labeled as potentially including upstream differences. Working comparisons use the existing private-index copy and empty-config context, avoiding repository filter commands during passive inspection.
- Split reconstructs the selected committed folder history. Its root tree must exactly equal that folder's selected commit tree before publication is offered. Working edits do not join publication. The result is pinned independently of future original commits.
- Publication previews the exact split OID, registered branch, actual push endpoints and shared preflight findings. Human approval is required. The selected profile, entire connection Choices/lease, sign-in scope/username and UI generation are checked; no token/password is persisted. Sending intent is durable before transport. Rejection/missing acknowledgement pauses; renewed review after explicit remote inspection is required, with no autosend or force push.

Limits: current candidate mutation/inspection requires native macOS/Linux ownership/access support; Windows and SSH repository paths refuse it. Git's contrib `subtree` helper must be installed. Inspection reports only helper file presence, without executing it. Actual helper/version/cwd-descriptor behavior, native ACL/race/checkout acceptance, credentials, network publication, conflicts and remote receipt behavior remain UNEXECUTED under the global hold. Shared command/approved-push routing and guarded history acceptance are parent-owned prerequisites. No subtree signing picker is added; isolated candidate commands retain the existing shared unsigned replay policy. Original #49 mentions Git 2.51 signing as background, not a requested signing control.

Bounds: 64 source registrations and 64 retained candidates; 2 MiB durable registry; 8 MiB per displayed patch; 2000 untracked paths / 1 MiB names. Limits return explicit errors. No automatic worktree/pin cleanup is introduced. Application refs are local implementation metadata and must not be mirror-pushed.

Validation is pure/recording/headless and compilation only. Exact application SHA, source hashes, command lines, exit codes and external plain-text log hashes are delivered in the owner handoff. No generated binary evidence is committed. Historical gates are not native acceptance for this unit.
