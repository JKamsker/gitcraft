# Native claim primitives — incomplete integration checkpoint

The OS crate now supplies retained `WorkspaceClaim`, `WorkspaceFence` and immutable grant primitives. They use three stable files (primary claim, operation fence and generation), kernel file locks and a create-new external anchor binding directory and file identities. The anchor lives beside the coordination root, outside the removable workspace. A missing/replaced file under an existing anchor is never recreated. An existing root with no anchor also fails closed rather than guessing whether initialization crashed. A torn anchor remains unresolved. Claim acquisition locks primary then operation fence before publishing the random generation. A fenced operation verifies actual namespace identities, exact generation and the continued presence of a kernel primary-lock owner. Drop only releases retained handles; it performs no cleanup, generation rewrite, retirement or dispatch.

Windows private directory creation now explicitly assigns the current user as owner, including when an elevated token's default owner differs. Anchor creation requests the rights needed to copy that held private directory's owner and protected DACL before writing anchor data. Actual file opens remain handle-relative; anchor names are create-new/no-follow and held against deletion on Windows. Unix checks owner, mode and single-link files. These semantics require a filesystem honoring the platform kernel file-lock contract; unsupported errors fail closed. File synchronization is performed, but containing-directory durability across machine/power loss is not claimed. Interrupted initialization can require manual resolution instead of silently repairing missing evidence.

The production authorization predicates are recording-tested against each replaced/missing root/primary/fence/generation identity, queued old generation, replaced anchor and torn generation. `CARGO_BUILD_JOBS=2 cargo +1.95.0 test --locked -p gitcraft-os recording -- --nocapture` passed 12 tests; OS Windows cross-check, all-target check and `git diff --check` passed. No real files, locks, helpers, children, contention/race fixture, Windows runtime, full suite or CI were exercised by these recording tests.

**These primitives are not yet connected to Workspace, native durable-owner launch, the Python/Perl backends or the external owner ledger.** They do not close R2 P1 or authorize runtime gates. The twelve complete claim-design schedules still require end-to-end production integration, recording coverage and independent source review. The seven feature ideas remain pending.
