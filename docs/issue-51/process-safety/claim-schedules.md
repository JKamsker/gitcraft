# Twelve claim schedules — injected source gates, runtime held

`src/remote/supervisor/workspace_recording_tests.py` and `workspace_recording_tests.pl` enter production claim/fence, publication, pending launch gate and external-ledger decisions with synthetic lock identities, scalar-memory handles and injected I/O. There are no real children, signals, locks, repository mutations or filesystem race fixtures. The Perl loader replaces kernel lock operations before compiling the production backend. Both suites have twelve named cases. Native equivalents exercise the production namespace/generation predicates, checked record write/sync/close routine, shared Service queue/spawn refusal decision, strict endpoint/receipt decoding and ledger finalization boundaries. These are deterministic boundary recordings, not kernel scheduling or complete live Service/transport execution.

| Design schedule | Recorded boundary and evidence |
| --- | --- |
| 1. Competing claimants and loser Drop | One actual claim branch publishes a generation; failed second claim closes only its descriptors and retains the winner. Workspace constructs cleanup-enabled ownership only after claim/open initialization succeeds. |
| 2. Equal PIDs, stale clocks/heartbeats | Actual claim remains denied despite identical PID and arbitrary heartbeat/clock fields; these fields provide no authority. |
| 3. Queued old-generation dispatch | Actual run wrapper acquires the machine fence and rejects stale generation before its inner operation can record or start. Native grant predicate rejects the same inputs. |
| 4. Paused admitted mutation and disconnect | Releasing the old primary while an actual operation fence is retained does not admit turnover; terminal operation release permits the next generation. |
| 5. Lease loss around record publication/ack/start | Injected collision/write/flush/sync/close failures deny handoff; checked native publication never releases after failure. A stopped production pending gate never starts. These separately test boundaries; no live publication/EOF race is claimed. |
| 6. Stop while pending | Repeated stopped-gate steps authorize no late release. Native Service's production queue/spawn refusal decision sees sticky ancestor cancellation. |
| 7. Publication/inventory overlap | Retained actual fence excludes turnover at pre/partial/complete record boundaries; the complete record remains discoverable after release. |
| 8. Unknown/colliding/replaced evidence | Record binding, changed proof, wrong/missing/malformed receipt and publication failures authorize no retirement. Native proof/receipt tests exercise the same failure classes. |
| 9. Lock replacement/unlink and stale release | Every synthetic namespace component replacement/missing entry is rejected; close does not rewrite generation. Native identity predicates cover all components. |
| 10. Independent CLEAR failures | `recording/clear_failures.py` overrides every git/rm command in actual CLEAR. Listing, worktree, metadata, ref/removal and verification failures return error. Nonzero/incomplete target results cannot finalize any backend ledger. CLEAR now removes the base after ref completion, so the old base-deleted-before-ref-failure order is absent. |
| 11. Worktree success/ref failure, retry/partial prune | Actual CLEAR fixture fails expected-OID ref deletion after recorded worktree removal. Partial record/cache prune retains a complete cleaned manifest with exact original capabilities. Native finalization stops at each injected failure; production close caches its first error and refuses further mutation from uncertain authority. |
| 12. Retirement refusal/shutdown | Injected retirement or lease-loss refuses completion, preserves original ledger records and performs no prune. Existing owned-controller/retirement recordings deny owner-kill authority and pin all removals to the authenticated identity. |

Supported limits: coordination needs trustworthy local filesystem kernel locks and stable canonical repository identity; namespace replacement or unsupported operations refuse. Evidence synchronization covers process crashes; containing-directory power-loss durability is not claimed. Native and remote endpoint kinds remain separate: a native ledger entry is recovered by native supervision, POSIX entries by Python/Perl. Crossing those owner kinds refuses conservatively. Deliberate target session escape on POSIX needs stronger kernel containment and is outside these process-group guarantees. Capture and inventory/proof bounds refuse while retaining evidence. No Windows/Linux/SSH/WSL runtime gate, live lock/contention/race fixture or normal Reader cancellation gate has run. Parent owns visualization API/test correction C1.
