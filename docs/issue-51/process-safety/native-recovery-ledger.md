# Native external recovery ledger — incomplete integration checkpoint

The actual native durable helper can prepare and finalize a checked cleanup while retaining its full mutation fence. Preparation validates the entire external inventory, bound generation/kind/nonce records, old cleanup manifests and cached receipts before any control request. It authenticates unresolved owners, caches exact record plus terminal proof outside the removable base, and rechecks records before allowing the cleanup command. Cancellation/deadline denies further recovery operations. A missing original record is accepted only when an existing completed-cleanup manifest preserves that exact record and authenticated receipt; an orphan cache is Unknown.

After the checked cleanup command and its postconditions succeed, finalization publishes a private manifest binding the anchor, generation, cleanup owner and exact recovered set. It retires prior endpoint artifacts with their authenticated cached proofs before pruning any records/caches. Partial pruning retains the manifest, enabling exact retry after a record was already deleted. Directory operations use retained private handles; file deletion validates exact bytes and remains relative to that directory. No directory pathname retirement is added. The current cleanup owner's record remains indexed for the next cleanup. The returned cleaned receipt contains only binding/count/digest, not endpoint capabilities.

Supported limits are 4,096 recovered owners, 64 MiB cumulative inventoried evidence, 40 MiB per cleanup manifest, bounded record/cache sizes and the existing finite operation deadline. Exceeding a bound preserves evidence and refuses cleanup. File synchronization and checked close cover process-crash publication; containing-directory power-loss durability and recovery after an unprovable supervisor crash are not claimed. Native durable input is separately encoded/capped at 64 MiB under a 96 MiB request cap for forthcoming bounded bundle chunks.
