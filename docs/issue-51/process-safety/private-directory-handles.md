# Handle-relative native files — WIP checkpoint

Native receipt retirement now uses a reusable retained private-directory object on both platforms. Unix opens fixed components with `openat`, no-follow/close-on-exec/nonblocking flags. Windows opens the component with `NtCreateFile` relative to the retained RootDirectory HANDLE, disables reparse processing, requests a synchronous regular-file handle and rejects opened reparse objects or multiple hard links. It preserves native NotFound/AlreadyExists errors for future coordination initialization. Receipt deletion still targets the checked opened HANDLE on Windows and the pinned directory on Unix. No subsequent parent pathname is used to open the receipt. Private directory ownership/mode or protected single-user DACL checks remain mandatory.

The same API provides retained file identity (Unix device/inode; Windows volume/FileId), bounded single-component names and create-new/update modes for the forthcoming stable claim anchor. These APIs do not establish workspace authority on their own; cross-process claim callers remain unchanged and unsafe runtime routes remain held. The public file-mode API never truncates an existing file merely by opening it.
