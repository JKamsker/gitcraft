# Pinned endpoint retirement — WIP checkpoint

Python opens the endpoint root with directory/no-follow flags, checks its owner and mode, reads the bounded private regular receipt relative to that descriptor and unlinks only fixed names relative to the same descriptor. Perl uses a no-follow directory filehandle, validates owner/mode and uses core Perl `chdir(FILEHANDLE)` to pin relative receipt/deletion operations; it restores its saved directory even after an error. Unsupported handle-based chdir fails closed.

Native Unix uses held directory and receipt descriptors and fixed `unlinkat`. Native Windows rejects reparse directories/files, checks the held directory's owner and protected single-user DACL, opens the receipt without write/delete sharing, checks its final parent against the held directory and marks that receipt HANDLE for deletion. These operations do not delete a substituted parent pathname. Empty endpoint directories remain; safely removing their final pathname requires a stronger atomic identity operation. Unknown receipts preserve artifacts.
