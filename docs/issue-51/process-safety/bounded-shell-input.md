# Bounded pooled-shell input — WIP checkpoint

Setup, idle ping, request and retirement ACK now use the same retained stdin writer. Their absolute deadline and task cancellation are checked while awaiting every write/flush result, including setup before readiness. A potentially submitted request is never retried. A failed ACK closes the connection while preserving the completed command result.

Unix makes only the owned pipe nonblocking and checks cancellation between partial writes. Windows uses one dedicated writer thread and `CancelSynchronousIo` against its retained JoinHandle HANDLE, repeated through retirement to cover the check/I/O race. No thread lookup or numeric signal target is used. Admission is limited to 64 active plus retained writers; pending input is capped at 96 MiB and one queued request per writer. A process-lifetime registry owns unfinished handles and permits until they can be joined. A failed monitor blocks new admission. Driver cancellation is not proof of completion: a platform operation that cannot cancel retains its handle, pipe and capacity and reports delivery/cleanup unknown. See Microsoft's [synchronous I/O cancellation contract](https://learn.microsoft.com/en-us/windows/win32/fileio/canceling-pending-i-o-operations).

Recording production-writer gates cover repeated would-block, partial delivery followed by cancellation, pending flush, zero/partial write failure and flush failure without success/replay. `CARGO_BUILD_JOBS=2 cargo +1.95.0 test --locked --lib recording -- --nocapture` passed 15 application and 9 OS tests. After changing retirement storage to a process-lifetime handle registry, `CARGO_BUILD_JOBS=2 cargo +1.95.0 test --locked -p gitcraft-os recording -- --nocapture` again passed all 9 OS tests. The all-target check and final OS Windows cross-check passed. `git diff --check` passed. No writer thread, actual transport, process fixture, helper, Windows runtime, SSH/WSL, full suite or CI was executed. Static review and later owned runtime gates remain required.
