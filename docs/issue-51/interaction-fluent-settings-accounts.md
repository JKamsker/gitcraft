# Fluent profile and connection settings

This incremental unit adds 70 paired English/German messages for profile,
connection/account and network settings. Whole explanatory patterns preserve CLI,
config and server tokens. Profile controls, signing guidance, author-host rules,
account folder captions, connection checks and HTTPS confirmation text resolve
the selected language. Existing finite settings-label rendering covers the three
additional network section/row names without changing search/preview identities.

`UserProfile::display_title()` localizes only the unnamed-profile fallback.
`title()`, generated config comments, user names, saved names and profile IDs stay
stable. Known network diagnostic lines remain raw in state and translate through
a finite paint adapter; unknown diagnostics, helper names, URLs and endpoint keys
remain opaque. Stored errors and worker/cancellation/authentication policies are
unchanged. Backend doctor/account result producers and shared error display
adapters still need their separately coordinated migrations.

Three new headless cases exercise the actual two-step profile deletion control,
inert account fields and an idle HTTPS page containing recorded status lines.
They check raw IDs/config text, unchanged account data, raw status retention,
opaque external diagnostics and English/German switching. The profile test emits
an in-memory request only. The account test never activates Check or Browse; the
network test has no repository, selected endpoint or job. Existing helper-redaction
and title cases are pure. Immutable checks and all-target compilation are bound
outside the repository in `/tmp/gitcraft-fluent-settings-accounts-validation.json`.
No actual config read/write, account check, connection action, native picker,
application process/network fixture, full suite or CI is claimed.

Previews, shared helper renderers, the full manual and remaining app/auxiliary
surfaces remain pending. Full Fluent localization is still WIP.
